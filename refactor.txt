================================================================================
TESTGEN — CODEBASE REORGANIZATION
Record of changes. Behaviour-preserving: no program logic was modified.
================================================================================

WHY
---
The tree had 25 loose files at the repo root, two competing file-extension
conventions, ~14 files that could not compile at all, a committed macOS binary,
and a 1509-line entry point holding three executor classes plus three test
suites plus main(). The goal was to make each module's job obvious from its
path, and to give the planned genetic-algorithm test-string generator a clear
home before that work starts.

Nothing was deleted. Dead files were moved to attic/, not removed.
No `git add` or `git commit` was run — staging is left to you. Plain `mv` was
used rather than `git mv`, so `git status` shows delete+add pairs; git detects
these as renames by content similarity when you commit.

5. SPLIT OF test_libapplication.cpp (1509 lines)
================================================================================

Pure extraction — no signature changed, no body edited, all 80 test strings
preserved verbatim, and the commented-out call sites in main() were left
exactly as they were.

  lines   26- 416  -> apps/executors.hh   TestMode + LibraryTestExecutor +
                                          TestExecutor + EcommerceTestExecutor
  lines  422- 747  -> apps/suites/restaurant_tests.cc   (25 tests)
  lines  753- 989  -> apps/suites/library_tests.cc      (25 tests)
  lines  995-1309  -> apps/suites/ecommerce_tests.cc    (30 tests)
  lines 1311-1510  -> apps/main.cc                      (main() only)

Suite headers were generated from the definitions, so the declarations cannot
drift from the bodies. Counts verified: 25 + 25 + 30 = 80.

DEVIATION FROM PLAN: executors.hh is header-only; there is no executors.cc.
The three executor classes were already fully inline in the class body, so
moving the bodies out would have meant retyping ~350 lines of method
definitions with ClassName:: prefixes — pure transcription risk for no gain.
Inline classes in a header are idiomatic and the organisational goal (main.cc
shrinking from 1509 to 214 lines) is fully met.

These 80 sequences matter beyond tidiness: 9 are explicitly labelled [UNSAT],
which makes the set a labelled corpus for validating the GA's fitness function
later.

  third_party/curl/     libcurl 8.5.0, built from source. The system had
                        libcurl.so.4 at runtime but no headers and no .so link.

                        ./configure --prefix=<repo>/third_party/curl \
                          --with-openssl --with-zlib --disable-ldap \
                          --disable-ldaps --disable-manual --without-libpsl \
                          --disable-static
                        make -j$(nproc) && make install

  third_party/include/nlohmann/json.hpp
                        The repo's own vendored copy, relocated from
                        includes/json.hpp. Verified as the genuine 24,596-line

                        #include <nlohmann/json.hpp>, and the old makefile had
                        no -Iincludes — so that copy was never actually being
                        read and the build silently depended on a system
                        package. It is now wired up properly.

The binary carries an RPATH to these directories, so it runs without
LD_LIBRARY_PATH. Total footprint ~40M; the source tarballs and curl build tree
were removed after installation.

================================================================================
9. KNOWN ISSUES LEFT ALONE (deliberately out of scope)
================================================================================

- README.md is partly fiction. Its "Writing Specifications" section documents a
  DSL — SymbolicVar, Block{.name=,.method=,.endpoint=}, Exists(), HasRole(),
  ValidToken() — that appears NOWHERE in the codebase. Real specs are built with
  make_unique<API>(pre, call, Response(post), "name") and FuncCall("in", ...).
  It also lists the restaurant backend at :9000 while the code uses :5002. Its
  "Project Structure" tree is now also out of date. Rewrite pending.

- The GA generator itself is a stub. Evaluate() in
  src/teststring/teststring_generator.cc only checks whether an API name exists
  in the spec. Since every gene is drawn from the spec's own name list in
  initialisation, crossover AND mutation, that check always succeeds — so
  fitness collapses to 100 + 10*length for every individual and the search
  degenerates to random sampling biased toward maxLen. Implementing real
  precondition checking (per docs/GA_pseudocode lines 52-81) is the actual task.

- Crossover() does not enforce minLen (only maxLen), so it can emit sequences
  shorter than the configured minimum.

- The three executor classes in apps/executors.hh are near-identical, differing
  only in factory type and default URL. Deduplicating them is a real cleanup but
  would have changed behaviour, so it was not done here.
